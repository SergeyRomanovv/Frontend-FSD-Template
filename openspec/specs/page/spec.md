# Page Specification

> Generated by openlore v1.2.0 on 2026-10-11 20:36

## Purpose

Reusable page-level UI widget that renders page content inside a full-height scrollable container
identified by PAGE_ID, and manages per-route scroll behavior (saving and restoring scroll position
stored in the application's ScrollSchema state).

## Requirements

> `src/widgets/Page/index.ts`

### Requirement: RenderPageContent

The system SHALL the page component must render its children inside a scrollable page container element tagged with the page_id identifier (for dom targeting and e2e tests), merging any custom classname with default page styles.

#### Scenario: RenderChildren
- **GIVEN** Arbitrary page children are passed to Page
- **WHEN** Page is rendered
- **THEN** Children appear inside the scrollable page container
- **AND** The container exposes the PAGE_ID identifier

#### Scenario: CustomClassName
- **GIVEN** A custom className prop is provided
- **WHEN** Page is rendered
- **THEN** The custom class is merged with the default page styles

### Requirement: ExposePageId

The system SHALL the module must export the page_id constant so tests, tooling, and other modules can reliably locate the page scroll container in the dom.

#### Scenario: StableIdentifier
- **GIVEN** The widget barrel file is imported
- **WHEN** PAGE_ID is accessed
- **THEN** A stable string identifier for the page container is returned

### Requirement: SaveScrollPosition

The system SHALL as the user scrolls the page container, the widget should capture the container's scroll position (throttled) and persist it in the store under the current route path (scrollschema).

#### Scenario: UserScrollsPage
- **GIVEN** User is on route /articles and scrolls the container to 500px
- **WHEN** The throttled scroll handler fires
- **THEN** Scroll position 500 is saved in the store under the /articles path

#### Scenario: NoScrolling
- **GIVEN** The container is not scrolled
- **WHEN** The page is displayed
- **THEN** No scroll-position write is dispatched

### Requirement: RestoreScrollPosition

The system SHALL when the page mounts or the active route changes, the widget should restore the previously saved scroll position for that route path from the store, defaulting to the top when no position was saved.

#### Scenario: ReturnToVisitedRoute
- **GIVEN** Scroll position 800 was previously saved for /articles
- **WHEN** User navigates back to /articles and the page mounts
- **THEN** The container's scrollTop is set to 800

#### Scenario: FirstVisitToARoute
- **GIVEN** No scroll position saved for the current path
- **WHEN** The page mounts
- **THEN** The container remains scrolled to the top (position 0)

## Technical Notes

- **Dependencies**: store (StateSchema / ScrollSchema scroll state), shared (classNames utility, throttle hook), react-router-dom (useLocation for current path)
