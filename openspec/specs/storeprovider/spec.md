# Storeprovider Specification

> Generated by openlore v1.2.0 on 2026-10-11 20:36

## Purpose

React context provider component that instantiates (or accepts) the Redux store and supplies it to
the application component tree, enabling descendants to read state and dispatch actions.

## Requirements

> `src/app/providers/StoreProvider/index.ts`

### Requirement: ProvideStore

The system SHALL render children inside a redux provider bound to a store created from optional preloaded state, so any descendant component can access state and dispatch via store hooks.

#### Scenario: ProvideStoreToChildren
- **GIVEN** StoreProvider is rendered with children
- **WHEN** The component mounts
- **THEN** Children are rendered within the Redux Provider
- **AND** Descendant components can read state via useSelector-like hooks
- **AND** Descendant components can dispatch actions via useDispatch-like hooks

#### Scenario: HydrateFromPreloadedState
- **GIVEN** An initialState is supplied (e.g. from server-side rendering or tests)
- **WHEN** StoreProvider creates its internal store
- **THEN** The store state is initialized with the provided preloaded slices

#### Scenario: DefaultInitialization
- **GIVEN** No initialState is supplied
- **WHEN** StoreProvider creates its internal store
- **THEN** The store initializes with each feature reducer's default state (counter, user, ui, scroll)

> `src/app/providers/StoreProvider/index.ts`

### Requirement: CreateReduxStore

The system SHALL create a fully configured redux store by combining all feature reducers, applying thunk middleware with extra argument, and conditionally enabling devtools composition in development.

#### Scenario: CreateStoreWithDefaults
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** createReduxStore is called without arguments
- **WHEN** The store is constructed
- **THEN** A store containing all combined feature reducers is returned
- **AND** Each slice (counter, user, ui, scroll) starts at its reducer-defined initial value

#### Scenario: CreateStoreWithPreloadedState
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A partial preloaded state is provided (e.g. only a counter slice)
- **WHEN** createReduxStore is called
- **THEN** The returned store's state is hydrated with the provided slices while unspecified slices fall back
to reducer defaults

#### Scenario: ThunkExtraArgumentAvailability
- **GIVEN** Thunk middleware is configured with a ThunkExtraArg
- **WHEN** An async thunk is dispatched
- **THEN** The thunk API exposes the configured extra argument (thunkAPI.extra) for use by features

#### Scenario: DevToolsEnabledInDevelopment
- **GIVEN** The app runs in development mode (__IS_DEV__)
- **WHEN** createReduxStore composes enhancers
- **THEN** Redux DevTools instrumentation is enabled

#### Scenario: DevToolsDisabledInProduction
- **GIVEN** The app runs in production mode
- **WHEN** createReduxStore composes enhancers
- **THEN** DevTools instrumentation is not applied to the store

### Requirement: DefineRootStateContract

The system SHALL define stateschema/rootstate as the aggregate of feature slices: counter (counter), user (user), ui (uischema), and scroll (scrollschema), all optional to support partial preloading.

#### Scenario: StateSlicesTyped
<!-- openlore-test: priority=high (auto) -->
- **GIVEN** StateSchema is referenced by the created store
- **WHEN** State is read via getState or typed hooks
- **THEN** The counter, user, ui, and scroll slices are accessible with correct types

#### Scenario: PartialStateHydrationSupport
- **GIVEN** Slices in StateSchema are optional
- **WHEN** A partial StorePreloadedState is passed to store creation
- **THEN** Type-checking permits hydrating only a subset of slices

### Requirement: DefineThunkConfig

The system SHALL define thunkconfig binding the thunk state to rootstate and the extra argument to thunkextraarg so feature thunks receive fully typed rejectwithvalue and thunkapi.extra.

#### Scenario: TypedThunkUsage
- **GIVEN** A feature thunk is declared with ThunkConfig
- **WHEN** The thunk accesses thunkAPI.getState, rejectWithValue, or extra
- **THEN** All thunk API members are correctly typed against RootState and ThunkExtraArg
