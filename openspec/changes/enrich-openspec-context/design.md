# Design

## Context

`openspec/config.yaml` mixes a curated context block with openlore
auto-detection leftovers (`Architecture: unknown`, a thin stack line, a raw
domain list). The config is read by every artifact generation run — see
proposal.md "Why". The `openlore:` footer key and `rag-manifest.json` are
machine-managed and regenerated by openlore.

## Goals / Non-Goals

**Goals:**
- One accurate, human-curated context block: methodology (FSD), tech stack
  categories with values grounded in `package.json`, verification entry
  points.
- Clear separation between curated text and machine-managed inventories.

**Non-Goals:**
- Changing `rules:` or `operations:` (curated earlier, working well).
- Version pinning inside the context — versions drift; the context states
  category-level truth, `package.json` holds exact versions.
- Touching the openlore footer or `rag-manifest.json`.

## Decisions

1. **`package.json` is the source of truth for stack values.** The context
   names categories with current values; a dependency upgrade that changes
   a category updates the context in the same change (spec scenario
   "Stack drift detection"). Alternative: pin versions in the context —
   rejected, it drifts on every upgrade.
2. **Flat prose context, no structured YAML lists.** The `context:` field
   is a single string injected verbatim into generation prompts; short
   labeled paragraphs stay scannable. Alternative: structured keys —
   rejected, the schema validates only the string field.
3. **Domain inventory stays machine-owned.** Raw domain lists live in the
   openlore footer and `rag-manifest.json`; the curated block references
   capabilities, not folder names.
4. **English retained** per the project's artifact-language decision.

## Risks / Trade-offs

- [Stack text drifts from `package.json` over time] → the openspec-config
  spec makes context updates part of dependency-changing changes; manual
  spot-check during propose runs.
- [Context bloat inflates every generation prompt] → cap the block at
  ~40 lines: categories only, no per-plugin enumeration.
